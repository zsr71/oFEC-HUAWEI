# 0. 当前代码对应关系（2026-05-07）

这份文档描述的是 `S0/S1/S3` 快速分类规则。当前代码已经把这套规则接入方案三的 hybrid prepass 中，对应开关是：

```cpp
HYBRID_ENABLE = true
HYBRID_USE_FAST_CLASSIFIER = true
```

如果同时设置：

```cpp
HYBRID_ENABLE_LIST = {0,0,0,0,0,1}
```

则只有最后一级 tile 会使用这套快速分类器，前面 tile 仍走旧 soft 路径。

当前代码中的分类枚举对应关系：

| 文档类别 | 当前代码 `HybridRowClass` | 当前处理 |
| --- | --- | --- |
| Clean | `Clean` | 校验通过后直接 `HardFinish` |
| ParityOnly | `ParityOnly` | 翻 overall parity 后校验，通过则 `HardFinish` |
| OneBCHError | `OneMain` | 用 `S1` 的 GF log 定位并翻 1 个 BCH 主体位 |
| OneBCHPlusParity | `OneMainPlusParity` | 翻 1 个 BCH 主体位，并按当前代码逻辑补 parity 位 |
| TwoBCHError | `TwoMain` | 复用现有 BCH t=2 hard decoder 兜底，成功且 `corrected_errors==2` 才 `HardFinish` |
| HardFail | `HardFail` | 保留为 `SoftDecode`，后续进入 MUX / Chase |

当前 `HardFinish` 行不会再跑 Chase。它会把硬纠得到的合法 256 位码字转换成固定后验：

```text
decoded_bit=0 -> +|HARD_LLR_MAG|
decoded_bit=1 -> -|HARD_LLR_MAG|
```

然后输出 `Y2 = Lpost - Lin`。当前默认 `HARD_LLR_MAG = 99.0f`。

注意：本文中的 two-error 闭式 locator / Chien search 仍是算法设计说明；当前代码的 `TwoMain` 分支还没有单独实现闭式 locator，而是调用现有 BCH 硬译码器。

---

这里我直接给你一个可落地的分类表和伪代码。默认前 255 位是 BCH 域内位置，第 256 位是扩展 parity 位，$S_0$ 是全码字奇偶校验 syndrome。

假设每个码字都有：

$$
S_0,\ S_1,\ S_3
$$

其中：

* $S_0$：扩展码整体 parity syndrome；
* $S_1$：一阶 BCH syndrome；
* $S_3$：三阶 BCH syndrome。

对 32 个 eBCH(256,239) 码字，可以逐个按下面逻辑分类。

---

# 1. 最重要的分类表

设第 $j$ 个码字的 syndrome 为：

$$
S_0^{(j)},\ S_1^{(j)},\ S_3^{(j)}
$$

分类规则如下。

| 类别 | 条件 | 解释 | 处理 |
| --- | --- | --- | --- |
| Clean | $S_0=0,\ S_1=0,\ S_3=0$ | syndrome 全零 | 直接跳过 |
| ParityOnly | $S_0=1,\ S_1=0,\ S_3=0$ | 可能只有扩展 parity 位错 | 翻 parity 位 |
| OneBCHError | $S_0=1,\ S_1\neq0,\ S_3=S_1^3$ | BCH 主体 1 bit 错 | 翻 BCH 对应位置 |
| OneBCHPlusParity | $S_0=0,\ S_1\neq0,\ S_3=S_1^3$ | BCH 主体 1 bit 错 + parity 位错 | 翻 BCH 位置 + parity 位 |
| TwoBCHError | $S_0=0,\ S_1\neq0,\ S_3\neq S_1^3$，且二次定位多项式有两个合法根 | BCH 主体 2 bit 错 | 翻两个 BCH 位置 |
| HardFail | 其他情况 | 超出 t=2 硬纠能力或 syndrome 不可解释 | 送 Chase / 软译码 |

---

# 2. 为什么要区分 $S_0$？

这个非常关键。

如果：

$$
S_1\neq 0,\quad S_3=S_1^3
$$

这说明 BCH 主体部分看起来像 **1 个错误**。

但它到底是：

```
只错了 BCH 主体 1 bit
```

还是：

```
BCH 主体错 1 bit，同时扩展 parity 位也错了
```

要靠 $S_0$ 区分。

因为：

* 只错 1 bit，总错误数是奇数，所以 $S_0=1$；
* BCH 主体 1 bit + parity 1 bit，总错误数是偶数，所以 $S_0=0$。

所以：

$$
S_0=1,\ S_1\neq0,\ S_3=S_1^3
$$

是 **OneBCHError**。

而：

$$
S_0=0,\ S_1\neq0,\ S_3=S_1^3
$$

是 **OneBCHPlusParity**。

这个点很容易漏掉。

---

# 3. TwoBCHError 怎么判断？

当：

$$
S_0=0,\quad S_1\neq0,\quad S_3\neq S_1^3
$$

它可能是 BCH 主体里 2 bit 错。

假设两个错误位置对应的域元素是：

$$
X,\ Y
$$

那么：

$$
S_1=X+Y
$$

$$
S_3=X^3+Y^3
$$

在 GF(256) 上可以得到：

$$
XY=\frac{S_1^3+S_3}{S_1}
$$

记：

$$
P=XY=\frac{S_1^3+S_3}{S_1}
$$

构造二次多项式：

$$
z^2+S_1z+P=0
$$

然后在 GF(256) 里搜索两个非零根。如果找到两个合法根 $X,Y$，就说明这是一个可解释的 2-bit error。

对应处理：

```
翻转 log(X) 和 log(Y) 对应的位置
```

注意：具体是 `log(X)` 还是 `log(inv(X))`，取决于你代码里 syndrome 的定义。如果你定义的是：

$$
S_1=\sum e_i\alpha^i
$$

那错误位置就是：

$$
i=\log_\alpha X
$$

如果你定义的是：

$$
S_1=\sum e_i\alpha^{-i}
$$

那就要用：

$$
i=-\log_\alpha X
$$

这个要和你现有的 BCH syndrome 计算保持一致。

# 3.1 硬件时序注意事项

`TwoBCHError` 在第一层快速分类里更准确地说只是 `TwoCandidate`。它必须再经过 BCH hard decoder，或者等价的 two-error locator + Chien search，才能知道最终是 `TwoMain` 还是 `HardFail`。

因此硬件上不能在 fast classification 这一拍直接得到完整 Chase 队列。推荐时序是：

```text
第 1 拍：计算 32 个码字的 S0 / S1 / S3
第 2 拍：完成 fast classification
        Clean / ParityOnly / OneBCHError / OneBCHPlusParity 可直接硬完成
        HardFailCandidate 可直接进 Chase 候选
        TwoCandidate 送 BCH / locator 确认
第 3 拍：TwoCandidate 确认返回
        成功 -> TwoMain / HardFinish
        失败 -> HardFail / Chase 候选
```

所以最终 Chase mask 应该等第三拍合成：

```text
chase_candidate_mask = chase_mask_fast | two_chase_mask
```

如果第二拍就先对确定的 Chase 行做 MUX 调度，第三拍返回的 two-fail 行会遇到 SISO 预算重排问题。第一版硬件实现建议等 `TwoCandidate` 确认完成后，再统一做 MUX / Chase 调度。

# 4. 逐个码字分类的伪代码

可以给每个码字一个类别：

```
enum class SyndromeClass {    Clean,    ParityOnly,    OneBCHError,    OneBCHPlusParity,    TwoBCHError,    HardFail};
```

分类逻辑：

```
SyndromeClass classify(uint8_t S0, GF S1, GF S3) {    if (S0 == 0 && S1 == 0 && S3 == 0) {        return SyndromeClass::Clean;    }    if (S0 == 1 && S1 == 0 && S3 == 0) {        return SyndromeClass::ParityOnly;    }    if (S1 != 0 && S3 == gf_mul(gf_mul(S1, S1), S1)) {        if (S0 == 1) {            return SyndromeClass::OneBCHError;        } else {            return SyndromeClass::OneBCHPlusParity;        }    }    if (S0 == 0 && S1 != 0) {        GF S1_cubed = gf_mul(gf_mul(S1, S1), S1);        GF P = gf_div(gf_add(S1_cubed, S3), S1);        auto roots = find_roots_z2_plus_a_z_plus_b(S1, P);        if (roots.size() == 2) {            return SyndromeClass::TwoBCHError;        }    }    return SyndromeClass::HardFail;}
```

其中 `gf_add` 在 GF(2^8) 里就是 XOR。

# 5. 对 32 个码字怎么批量处理？

你可以维护一个数组：

```
std::array<SyndromeClass, 32> cls;
```

然后：

```
for (int j = 0; j < 32; j++) {    cls[j] = classify(S0[j], S1[j], S3[j]);}
```

然后按类别处理：

```
for (int j = 0; j < 32; j++) {    switch (cls[j]) {        case SyndromeClass::Clean:            // 不处理            break;        case SyndromeClass::ParityOnly:            // 翻转第 256 个扩展 parity bit            flip_parity_bit(j);            break;        case SyndromeClass::OneBCHError:            // pos = log(S1[j])            flip_bch_position(j, log_table[S1[j]]);            break;        case SyndromeClass::OneBCHPlusParity:            // pos = log(S1[j])            flip_bch_position(j, log_table[S1[j]]);            flip_parity_bit(j);            break;        case SyndromeClass::TwoBCHError:            // 通过二次多项式求两个根，然后翻转            correct_two_bch_errors(j, S1[j], S3[j]);            break;        case SyndromeClass::HardFail:            // 加入 Chase / 软译码队列            hard_fail_list.push_back(j);            break;    }}
```

# 6. 最终调度优先级

对 32 个码字，建议优先级这样定：

```
Clean    直接跳过ParityOnly    直接翻 parity bitOneBCHError    直接 BCH 单错误纠正OneBCHPlusParity    翻 BCH 位置 + parity bitTwoBCHError    BCH 双错误纠正HardFail    送 Chase / 软译码
```

如果你要给 Chase 资源排序，那么：

```
HardFail 最高优先级TwoBCHError 可疑时次高OneBCHError / OneBCHPlusParity 一般不用 ChaseClean 完全不用处理
```

更工程化一点：

```
class = Clean:    skipclass = ParityOnly / OneBCHError / OneBCHPlusParity / TwoBCHError:    hard correctionclass = HardFail:    Chase / soft decoding
```

# 7. 一个完整的分类例子

假设某个码字满足：

$$
S_0=1,\quad S_1=0,\quad S_3=0
$$

那么它是：

```
ParityOnly
```

翻扩展 parity 位即可。

---

如果：

$$
S_0=1,\quad S_1\neq0,\quad S_3=S_1^3
$$

那么它是：

```
OneBCHError
```

翻 BCH 主体一个位置。

---

如果：

$$
S_0=0,\quad S_1\neq0,\quad S_3=S_1^3
$$

那么它不是 clean，也不是普通单错，而是：

```
OneBCHPlusParity
```

需要同时翻：

```
BCH 主体 1 bit + 扩展 parity bit
```

---

如果：

$$
S_0=0,\quad S_1\neq0,\quad S_3\neq S_1^3
$$

则尝试二错误定位。如果能找到两个合法根，就是：

```
TwoBCHError
```

否则：

```
HardFail
```

---

# 8. 最简洁版本

你可以直接按这个顺序判断：

```
1. S0=0, S1=0, S3=0   -> Clean2. S0=1, S1=0, S3=0   -> ParityOnly3. S1!=0 且 S3=S1^3   -> 如果 S0=1: OneBCHError   -> 如果 S0=0: OneBCHPlusParity4. S0=0, S1!=0, S3!=S1^3   -> 尝试二错误定位   -> 成功: TwoBCHError   -> 失败: HardFail5. 其他   -> HardFail
```

一句话总结：

> 对 32 个码字，先用 $S_0,S_1,S_3$ 分成 clean、parity-only、1-error、1-error+parity、2-error 和 hard-fail；前五类直接硬处理，只有 hard-fail 进入 Chase / 软译码队列。
