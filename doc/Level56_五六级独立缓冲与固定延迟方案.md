# 第五级／第六级独立缓冲、固定区与共享译码资源方案

## 1. 方案结论

本方案按一块连续物理 SRAM 建模，但在控制上为第五级和第六级分别维护缓冲状态、先进先出队列和解码窗口。两级只共享译码资源，不再共用同一个缓冲状态，也不要求两级的三十二码字任务一起完成、一起退休或一起移动。

总体结构为：

```text
第五级初始解码区 22 个子块行
    → 固定区 D=2 个子块行，即 32 个全局矩阵行
    → 第五级独立缓冲区 r1 个子块行
    → 第六级初始解码区 22 个子块行
    → 第六级独立缓冲区 r2 个子块行
```

其中：

```text
r1 = 第五级独立 R_buf；
r2 = 第六级独立 R_buf；
第一版通常取 r1 = r2 = 配置的 R_buf；
D = 2 个子块行 = 32 个全局矩阵行。
```

每个调度时刻，整个 SRAM 固定向顶部推进两个子块行：第五级初始区底部进入前四级的新结果，SRAM 顶部推出最老的两个子块行。第五级窗口和第六级窗口在各自允许范围内独立调整位置。

每轮资源分配时，第五级和第六级分别从自己的当前窗口提供三十二个候选码字。两级都可服务时，共形成六十四个候选码字，共同竞争同一份八个四码分组机会和共享的硬判／软判译码资源。这六十四个码字只是本轮候选集合，不是一个共同退休的先进先出队列项。

本方案继承原有缓冲控制的核心规律：某一级一个时刻完成零个、一个或两个三十二码字任务时，该级窗口分别向缓冲顶部移动、保持不动或向初始位置退回。这里没有提出新的窗口移动算法，只是把原来的一套规则分别、独立地应用到第五级和第六级，所以同一时刻两级完成的任务数可以不同，窗口移动结果也可以不同。

## 2. 设计目标

本方案主要解决旧结构中的两个问题：

1. 旧结构把第五级与第六级的三十二码字任务绑定成一个六十四码字队列项，只要其中一侧没有完成，另一侧也不能独立向前推进；
2. 旧结构在当前任务没有用满八个四码分组机会时，剩余机会不能充分用于后续任务，造成共享译码资源空闲、缓冲积压难以下降。

新结构需要达到：

```text
第五级缓存自己的任务；
第六级缓存自己的任务；
第五级和第六级分别移动、分别退休、分别到达边界；
某一级暂时没有可服务任务时，不阻塞另一级；
两级有任务时，尽量共同用满共享的八个四码分组机会；
波峰时允许积压进入缓冲，波谷时能够逐步排空缓冲。
```

## 3. 不改变的内容

本方案不改变以下内容：

- 编码端连续编码与发射码流；
- 信息比特、编码比特和历史位置之间的映射；
- 帧长、交织器、BCH 结构和已知前缀；
- 第五级相对于前四级的固定初始位置；
- 现有四码分组的分组方法；
- 每个时刻最多八个四码分组机会；
- 第五级和第六级共享硬判／软判译码资源；
- 分组先按待译码码字数量从多到少排序，同负载时第五级优先；
- 原有缓冲区的窗口移动、边界顶出和统计口径，只是分别应用到两级。

固定区不是编码端插入的零行、空行、保留行或额外符号。它是接收端连续 SRAM 中用于拉开第五级和第六级初始位置的一段正常数据驻留空间；编码端无需修改。

## 4. 单位和参数

本文使用两种“行”，必须明确区分：

```text
一个子块行 = 16 个全局矩阵行；
一个正常推进单位 = 2 个子块行 = 32 个全局矩阵行；
一个三十二码字任务 = 2 个子块行中的 32 个 BCH 码字。
```

定义：

| 符号 | 含义 | 第一版取值 |
|---|---|---:|
| `H` | 每一级解码窗口的高度 | 22 个子块行 |
| `P` | 每个时刻的数据推进量 | 2 个子块行 |
| `D` | 位于第五级初始区和第五级缓冲区之间的固定区 | 2 个子块行 |
| `x` | 固定区换算成全局矩阵行 | 32 行 |
| `r1` | 第五级独立缓冲容量 | 第五级 `R_buf` |
| `r2` | 第六级独立缓冲容量 | 第六级 `R_buf` |

因此：

\[
x=16D=32
\]

所有物理区间和窗口位置公式都用“子块行”表示；只有对外说明固定区时，才把 `D=2` 换算成 `x=32` 个全局矩阵行。

## 5. 物理布局和坐标范围

以第五级初始解码区的第一行为物理位置 `0`。五个连续区域为：

| 区域 | 起始位置 | 结束位置，不含右端 | 长度 |
|---|---:|---:|---:|
| 第五级初始解码区 | `0` | `H` | `H=22` |
| 固定区 | `H` | `H+D` | `D=2` |
| 第五级独立缓冲区 | `H+D` | `H+D+r1` | `r1` |
| 第六级初始解码区 | `H+D+r1` | `2H+D+r1` | `H=22` |
| 第六级独立缓冲区 | `2H+D+r1` | `2H+D+r1+r2` | `r2` |

总长度为：

\[
L=2H+r_1+D+r_2=46+r_1+r_2
\]

这里的 `46` 是：

```text
第五级 22 行 + 固定区 2 行 + 第六级 22 行。
```

### 5.1 一个具体布局例子

若第一版取：

```text
D=2，r1=32，r2=32，单位均为子块行，
```

则整块 SRAM 的逻辑区间为：

| 区域 | 区间 |
|---|---|
| 第五级初始解码区 | `[0,22)` |
| 固定区 | `[22,24)` |
| 第五级独立缓冲区 | `[24,56)` |
| 第六级初始解码区 | `[56,78)` |
| 第六级独立缓冲区 | `[78,110)` |

此时第五级窗口起点可在 `0～34` 之间变化；第六级窗口起点可在 `56～88` 之间变化。第五级窗口移动到最远位置时覆盖 `[34,56)`，第六级窗口处于初始位置时覆盖 `[56,78)`，两个物理窗口在边界处相接但不重叠。

这里说的是物理 SRAM 区间不重叠。代码实现时仍必须逐个全局逻辑坐标检查第五级写回和第六级读取的关系，不能只根据大区间不重叠就跳过坐标级验证。

## 6. 第五级和第六级解码窗口

两个解码窗口的高度均为 `H=22` 个子块行。

### 6.1 第五级窗口

设第五级窗口起点为 `p5(t)`。初始时：

\[
p_5(0)=0
\]

第五级窗口只能在第五级初始区、固定区和第五级缓冲区共同形成的范围内移动，因此：

\[
0\le p_5(t)\le r_1+D
\]

第五级窗口覆盖：

\[
[p_5(t),\ p_5(t)+H)
\]

当 `p5(t)=r1+D` 时，第五级窗口到达允许范围的最顶部，其窗口上边界正好到达第六级初始解码区的起点。

因此，固定区 `D` 不只是拉开两个初始解码区的位置；按照本方案，它也客观上增加了第五级窗口可向上移动的空间。第五级的最大可移动距离为：

\[
A_5=r_1+D
\]

### 6.2 第六级窗口

第六级初始解码区的起点为：

\[
b_6=H+r_1+D
\]

设第六级窗口绝对起点为 `p6(t)`。初始时：

\[
p_6(0)=b_6
\]

第六级窗口只能在第六级初始解码区和第六级独立缓冲区内移动，因此：

\[
b_6\le p_6(t)\le b_6+r_2
\]

第六级窗口覆盖：

\[
[p_6(t),\ p_6(t)+H)
\]

第六级的最大可移动距离为：

\[
A_6=r_2
\]

### 6.3 两个窗口独立移动

第五级和第六级共享译码资源，但两个窗口的位置互不绑定：

```text
第五级窗口是否移动，只看第五级本时刻完成了多少个任务；
第六级窗口是否移动，只看第六级本时刻完成了多少个任务。
```

因此，同一个时刻完全可以出现：

```text
第五级完成两个任务，窗口向初始位置退回；
第六级只完成一个任务，窗口保持不动。
```

也可以出现相反情况。两级不要求完成数量相同。

## 7. 数据的固定推进

每个正常时刻都引入 `P=2` 个新的子块行。概念上可以理解为：

```text
底部进入前四级产生的两个新子块行；
现有数据整体向顶部前进两个子块行；
最顶部的两个最老子块行离开当前存储范围。
```

软件第一版不必真的在内存中搬动全部数据。它可以继续沿用现有抽象：

```text
work_llr 保存全帧唯一的当前软信息；
窗口位置和队列项保存逻辑行号；
通过更新逻辑起点和队列状态等价表示数据向前推进。
```

也就是说，本节描述的是流水和地址关系，不要求第一版创建五段真实数组或每时刻复制整块软信息。

### 7.1 一个时刻内的统一处理顺序

为了让软件结果与物理含义一致，每个正常时刻按下面的顺序理解：

```text
一、接收本时刻从前四级进入的两个新子块行；
二、按照当前两个窗口位置，分别形成第五级和第六级的当前任务；
三、把两个当前队首放入同一轮候选集合，执行第一轮共享调度；
四、先完成第一轮写回，再判断两级各自是否完成并退休；
五、若有剩余机会且满足双批规则，从写回后的全局软信息重新读取，执行第二轮；
六、分别统计本时刻第五级和第六级完成的任务数；
七、若本时刻开始时某一级已经到顶，对该级原队首执行既有强制顶出判断；
八、分别更新第五级和第六级的窗口状态，得到下一时刻位置；
九、进入下一时刻。
```

在稳态下，物理数据每时刻都前进两个子块行，因此两级各自都会按数据有效性产生一个新的三十二码字任务。启动和帧尾可能只有一级产生有效任务，此时另一侧不应被阻塞。

## 8. 两个独立队列

第五级和第六级分别维护自己的先进先出队列。

### 8.1 第五级队列

```text
每个队列项包含第五级的 32 个码字；
保存该任务的逻辑行号、待处理码字、服务次数和退休原因；
只受第五级窗口位置和第五级边界控制；
正常完成、完整早停或强制顶出后，从第五级队列退休。
```

### 8.2 第六级队列

```text
每个队列项包含第六级的 32 个码字；
保存该任务的逻辑行号、待处理码字、服务次数和退休原因；
只受第六级窗口位置和第六级边界控制；
正常完成、完整早停或强制顶出后，从第六级队列退休。
```

### 8.3 不再绑定成一个共同队列项

新方案明确禁止把下面两项重新绑定：

```text
第五级的一个 32 码字任务
+ 第六级的一个 32 码字任务
= 一个必须共同完成和共同退休的 64 码字队列项。
```

六十四个码字只表示同一个调度轮次最多同时看见的候选集合，不表示队列的最小项。第五级任务和第六级任务可以分别完成、分别保留、分别顶出。

两条队列各自保持先进先出：本级旧队首尚未退休时，本级后续任务不能越过它接受普通服务。第五级的先进先出顺序不约束第六级，第六级的先进先出顺序也不约束第五级。

### 8.4 任务分类与后续重试

任务分类完全继承旧 FIFO 实现。一个任务第一次真正成为可服务队首时，从当前 `work_llr` 读取输入，并完成本级三十二个码字的 EarlyStop、Hybrid 类别和 HISO/SISO 资源资格判定。分类结果进入该任务的生命周期状态。

任务获得普通服务后若仍有 pending，下一次服务时：

```text
重新从当前 work_llr 读取实际软信息；
保留该任务首次正式分类得到的 EarlyStop、Hybrid 类别和资源资格；
保留每个码字的 AlreadyDecoded、pending 和写回状态；
已完成码字不重新分类、不重复解码、不重复写回；
只让尚未完成的码字继续参加共享调度。
```

因此，“重新读取当前软信息”和“重新执行任务分类”是两件事：前者每次正式服务都要做，后者只在任务首次正式进入服务时做。

为了判断零资源完整早停，可以预先检查刚暴露的队首。如果该任务不是完整早停，而且本时刻已经没有普通服务名额或 entry，则这次检查不得固化为该任务的首次正式分类；等它真正获得普通服务时，要从当时的 `work_llr` 重新读取并完成首次正式分类。这一细节也完全继承旧实现。

## 9. 每个时刻的共享资源调度

### 9.1 第一轮候选集合

每个正常调度时刻先查看两级各自的当前队首：

```text
第五级队首可服务：提供 32 个第五级候选码字；
第六级队首可服务：提供 32 个第六级候选码字；
两级都可服务：共提供 64 个候选码字；
只有一级可服务：仅使用该级提供的 32 个候选码字。
```

某一级没有任务、尚未进入有效区域、已经排空或处于启动／帧尾空缺时，另一侧不被它阻塞。

### 9.2 四码分组和资源上限

两级都可服务时，候选集合仍按现有方式组织为十六个四码分组：

```text
前八组：第五级的 32 个码字；
后八组：第六级的 32 个码字。
```

每个时刻的资源限制保持：

\[
E_1(t)+E_2(t)\le 8
\]

其中 `E1(t)`、`E2(t)` 分别是第一轮和第二轮实际使用的四码分组机会数。

硬判和软判译码资源同样由第五级与第六级共享，不为两级分别复制一套容量。

### 9.3 第五级优先的准确含义

第一版保持原有选择：

```text
先比较每个四码分组中仍需译码的码字数量；
待译码码字多的分组优先；
两个分组负载相同时，第五级分组优先；
同一级、同负载时，按原有组号顺序处理。
```

“第五级优先”不是第五级无条件独占八个机会。例如：

```text
第五级某组有 2 个待译码码字，
第六级某组有 4 个待译码码字：
    第六级组优先；

第五级某组和第六级某组都各有 2 个待译码码字：
    第五级组优先。
```

## 10. 每个时刻最多处理两批的准确含义

第一版沿用已经确定的双批填充规则：每个时刻最多执行两轮普通资源分配。对每一级而言，这意味着本时刻最多接触两个普通的三十二码字队列项；它不表示重新建立一个六十四码字共同队列。

每轮普通资源分配开始前，先分别清理两条队列队首连续出现的完整早停任务：

```text
检查第五级队首：
    若本级 32 个码字全部 EarlyStop，零普通资源退休并继续检查第五级新队首；
    直到第五级队首为普通任务或第五级 FIFO 为空；

检查第六级队首：
    若本级 32 个码字全部 EarlyStop，零普通资源退休并继续检查第六级新队首；
    直到第六级队首为普通任务或第六级 FIFO 为空；

再用两级当前的第一个普通队首形成本轮候选集合。
```

第五级和第六级的完整早停退休互不绑定。为使日志顺序稳定，同一检查阶段可以固定先记录第五级、再记录第六级；这只影响日志排列，不表示第五级占用或抢占普通资源。

### 10.1 第一轮

```text
读取第五级和第六级各自当前可服务的队首；
形成候选集合；
按负载排序、同负载第五级优先；
使用最多八个四码分组机会；
执行译码并写回 work_llr；
分别判断第五级任务和第六级任务是否正常完成；
各级已完成任务在自己的队列中独立退休。
```

第一轮可能同时包含两级任务，也可能只有一级任务。某一级没有有效队首时，另一侧仍可接受服务。

### 10.2 第二轮

只有第一轮实际使用少于八个机会，并且至少一条队列还有可服务任务时，才进入第二轮：

```text
先完成第一轮全部写回和独立退休；
从更新后的 work_llr 重新读取；
分别连续清理第一轮之后新暴露的本级完整早停队首；
重新查看第五级、六级各自更新后的队首；
只对新暴露且首次获得普通服务的队首完成首次正式分类；
已经分类的原队首保留分类和生命周期状态；
根据当前两个队首的未完成码字重新进行 Group4 负载统计和排序；
只使用第一轮剩余的四码分组机会。
```

第二轮结束后，即使仍有剩余机会，本时刻也不进行第三轮。

这对应会议中“剩余机会可以给后面的任务，但不能继续给下下一个任务”的限制。

还要特别说明一个不会发生的情况：

```text
第一轮只使用了三个机会，某个参加第一轮的普通任务却仍未完成，
然后把剩余五个机会让给别的任务。
```

按照现有四码分组调度规则，只要本轮候选集合中仍有普通待译码内容，调度器就会继续使用本轮剩余机会，直到候选任务完成或本时刻的机会全部用完。因此，第一轮使用少于八个机会时，参加第一轮的普通任务应当已经完成。第二轮使用的是完成并写回后重新暴露出来的新队首，而不是越过未完成队首。

### 10.3 两级完成数仍然可以不同

“参加第一轮的未完成普通任务会用满剩余机会”不等于“两级每时刻完成数量必须相同”。例如第一轮使用全部八个机会以后，可以出现：

```text
第五级当前任务完成并退休；
第六级当前任务仍未完成、继续留在队首；
```

此时没有剩余机会，所以本时刻不执行第二轮。到下一个时刻，候选集合为：

```text
第五级的新队首
+ 第六级仍未完成的原队首。
```

反过来也一样。

还可以出现下面的合法例子：

```text
第一轮：第五级旧队首和第六级旧队首都完成，共使用三个机会；
第二轮：用剩余五个机会服务两级新队首；
第二轮结束：第五级新队首完成，第六级新队首没有完成。
```

那么本时刻第五级完成两个任务，第六级完成一个任务。第五级窗口按“完成两个”更新，第六级窗口按“完成一个”更新。两级独立队列和独立窗口的意义正是在这里：一侧是否更换队首、窗口如何移动，不由另一侧的完成数量决定。

## 11. 两级分别沿用原有窗口移动规则

这一节不是新增缓冲算法，而是把原来一套缓冲窗口更新规则分别用于第五级和第六级。

定义相对移动量：

\[
q_5(t)=p_5(t)
\]

\[
q_6(t)=p_6(t)-b_6
\]

并定义：

```text
C5(t)：时刻 t 内第五级正常完成或完整早停并退休的三十二码字任务数；
C6(t)：时刻 t 内第六级正常完成或完整早停并退休的三十二码字任务数。
```

强制顶出只表示为固定输入节拍腾出位置，不表示译码完成，因此不计入 `C5(t)` 或 `C6(t)`。

这里必须区分“服务”和“完成”：

```text
本级任务获得一次普通服务，但服务后仍有待译码码字：
    它继续留在本级队首，不给 Ci(t) 加一；

本级任务经过普通服务后全部完成并写回，或者通过完整早停直接完成：
    它从本级队列退休，给 Ci(t) 加一；

本级任务因到顶而被强制顶出：
    它虽然从队列退出，但不是译码完成，不给 Ci(t) 加一。
```

所以窗口移动只由本级本时刻的完成退休数决定，与本时刻调用了几轮普通服务、实际用了几个四码分组机会不是一回事。

第五级与第六级分别更新：

\[
q_i(t+1)=\operatorname{clip}\left(q_i(t)+P-PC_i(t),\ 0,\ A_i\right)
\]

其中 `clip(z,0,A)` 表示把结果限制在 `0～A`：小于零时取零，大于 `A` 时取 `A`。

其中：

\[
P=2,\qquad A_5=r_1+D,\qquad A_6=r_2
\]

主干情况为：

| 该级本时刻完成任务数 | 该级窗口变化 | 缓冲含义 |
|---:|---|---|
| `0` | 向本级缓冲顶部移动 2 行 | 进入量大于完成量，积压增加 |
| `1` | 位置不动 | 进入两个子块行，也排走一个两行任务，正好平衡 |
| `2` | 向本级初始位置退回 2 行 | 完成量大于进入量，积压减少 |

完整早停完全继承旧实现：它不消耗普通 Group4 entry，也不占用每时刻最多两个普通任务的名额；只要本级队首连续满足完整早停，就可以在同一个时刻按本级先进先出顺序连续完成并退休。因此，`Ci(t)` 可以大于 `2`。窗口仍使用同一个公式更新，并在本级初始位置截断，不允许越过下界。

### 11.1 用原实现的剩余缓冲空间表示

也可定义该级距离缓冲顶部还剩多少移动空间：

\[
S_5(t)=A_5-q_5(t)
\]

\[
S_6(t)=A_6-q_6(t)
\]

则：

\[
S_i(t+1)=\operatorname{clip}\left(S_i(t)-P+PC_i(t),\ 0,\ A_i\right)
\]

需要注意：

```text
r1、r2 是两级各自配置的独立 R_buf；
第五级因为还可以使用固定区 D，所以最大可移动空间 A5=r1+D；
第六级最大可移动空间 A6=r2。
```

这正是“固定区客观上也增加第五级可承受移动空间”的含义。

第一版代码中的配置入口为：

```text
LEVEL5_BUFFER_ROWS：单独设置 r1；
LEVEL6_BUFFER_ROWS：单独设置 r2；
LEVEL56_BUFFER_ROWS：兼容旧实验命令；未单独设置 r1/r2 时，同时作为两级容量。
```

因此，旧扫描脚本只设置 `LEVEL56_BUFFER_ROWS` 时仍会得到 `r1=r2`；需要
研究非对称缓冲容量时，再分别设置前两个参数。

这一写法与原实现的状态量含义一致：`S` 表示还剩多少缓冲移动空间，初始时处于最大值；没有完成任务时每拍消耗两个子块行，完成一个任务时刚好抵消固定输入，完成两个任务时恢复两个子块行。新方案只是把原来的一个 `S(t)` 拆成独立的 `S5(t)` 和 `S6(t)`。

## 12. 缓冲顶部与强制顶出

每一级分别判断自己是否到达顶部：

```text
第五级顶部：q5(t)=A5=r1+D，也就是 S5(t)=0；
第六级顶部：q6(t)=A6=r2，也就是 S6(t)=0。
```

边界语义沿用原有方案：

```text
本时刻开始时，该级窗口已经到达顶部；
该级原队首仍可获得本时刻合法的最后一次服务机会；
如果服务后仍未完成，则把该级原队首中未完成的码字标为强制顶出；
已经完成并写回的码字保持不变；
强制顶出的码字不计为译码成功，也不计为正常完成；
该级原队首以强制顶出原因退休，为后续数据腾出位置。
```

第五级到边界只处理第五级自己的队首；第六级到边界只处理第六级自己的队首。不得因为一侧被强制顶出，就自动顶出另一侧任务。

## 13. 五、六级之间的数据关系

第五级与第六级仍然存在原有码图中的历史依赖，但本方案不再使用“某个第五级任务编号完成后，人工放行某个第六级任务编号”的额外等待状态。

两级之间的关系由以下内容自然决定：

```text
连续 SRAM 中的物理排列；
位于第五级初始区与第五级缓冲区之间的固定两个子块行区域；
每个时刻两个子块行的数据推进；
第五级和第六级各自当前窗口的位置；
既有全局逻辑坐标和历史读写映射。
```

因此，运行时两个窗口之间的实际距离不是固定的任务编号差，而是：

\[
\Delta(t)=p_6(t)-p_5(t)
\]

由于两个窗口可以独立移动，`Δ(t)` 可以变化。固定的是物理 SRAM 中 `D=2` 这段区域及两个初始窗口的物理锚点，不是“第六级永远等待第五级某编号任务”的软件门控规则。

第一轮写回后，第二轮必须重新从更新后的 `work_llr` 读取。这条顺序继续保留，用来保证同一时刻第二轮看到第一轮已经提交的完整状态。

## 14. 启动阶段

启动阶段完全沿用原实现关于已知前缀、第一解码窗口和有效帧范围的处理，不新增人工预填规则，也不要求人为指定一个“全局任务编号”。新方案只是在原有第五级起点不变的基础上，根据物理布局计算第六级的起点：

```text
第五级窗口初始起点为 0；
第六级窗口初始起点为 H+r1+D；
第五级、六级分别根据本级窗口内容是否有效决定能否产生队列项。
```

第五级和第六级的队列编号彼此独立，都可以从本级的零号任务开始。这里的“零号任务”只是日志中的本级先进先出序号；任务实际读取哪两个子块行、对应哪些全局矩阵行，由原有窗口坐标和上述两个窗口起点自动计算，不能人为再指定一套编号映射。

当前已知前缀继续提供原实现启动所需的历史数据，不需要编码端插入任何新行。如果按照原实现的预填方式，第一个正常调度时刻两个窗口都已经有效，就直接形成第五级三十二码字加第六级三十二码字的共同候选集合。如果在逐时刻物理有效性模型中暂时只有一级窗口有效，则该级可以单独使用共享资源，不能等待另一级。

实现时只需用测试核对以下内容，不属于方案选择：

```text
第五级零号任务读取的坐标与原实现一致；
第六级零号任务的坐标等于按 H+D+r1 偏移后应读取的坐标；
没有在有效帧范围之外生成任务；
两级各自的任务编号都连续且不重复。
```

这些检查只是确认程序正确实现已经确定的地址关系，不改变调度策略和稳态窗口移动规则。

## 15. 帧尾阶段

第一版完全继承旧实现的 `drain=ON`：只排空已经进入 FIFO 的任务，不新增物理 SRAM 尾部刷新。所有正常输入时刻结束后，不再运行第一至第四级，不再引入任何新任务，也不继续通过物理推进产生第五级或第六级任务；只让已经进入两条 FIFO 的队首继续按新方案的共享调度规则获得服务，直到两条 FIFO 都为空。

分别对两条队列执行：

```text
正常输入阶段结束；
停止第五级和第六级的新任务到达；
不再生成任何新的 FIFO 项；
已有第五级、六级队首继续共享资源；
按照两轮、完整早停和分别退休规则处理；
直到第五级 FIFO 和第六级 FIFO 都为空。
```

这种方式与现有离线 BER／等价性验证的 drain 含义完全一致，也便于和旧实验直接比较。物理 SRAM 尾部刷新不属于第一版方案；如果后续需要研究，应建立独立模式和独立实验，不能改变本方案中 `drain=ON` 的含义。

帧尾某一级没有任务时，另一级仍可独立使用共享资源；不能因为一侧结束而让另一侧停止。

最后一个有效任务不需要人为指定。它由正常输入阶段的原有帧长、有效窗口范围和各级地址公式自动决定；进入 drain 后不得为了排空而生成新的任务。

实现时需要用测试核对“最后一个有效任务只到达一次、只退休一次、没有遗漏，也没有在帧外多生成任务”。这是防止帧尾少译或重复译码的正确性检查，不是需要另行决定的调度规则。
