# Level 5/6 Buffered FIFO：第 1 步译码机会覆盖性测试

## 1. 测试目的

本测试只验证原始问题是否已经消除：

> 在 Buffered FIFO 中，是否存在一个初始为非 EarlyStop 的 code，在整个生命周期内从未获得 HISO 或 SISO 的译码机会？

本测试不比较 Buffered FIFO 与独立 `L5=32/32、L6=32/32` 的最终 BER；该 A/B 等价性问题属于后续第 2 步。

## 2. 被分析的既有运行

## 3. 分析方法

CSV 的每一行表示一个 batch/code 在一次 FIFO 服务尝试中的状态。一个 pending code 在后续时刻重新进入调度时，可能有多条记录。

本测试以以下键聚合整个生命周期：

```text
(buffered_batch, code)
```

其中 `code=1..64`，前 32 个属于 Level 5，后 32 个属于 Level 6。

对于每个唯一 code，统计：

- 初次出现时的 `early_stop_hit`；
- 整个生命周期中是否曾出现 `EarlyStopAction`；
- 整个生命周期中是否曾出现 `HisoDecode`；
- 整个生命周期中是否曾出现 `SisoDecode`；
- 最后一条生命周期记录中的 `already_decoded`、`pending`、`forced_evicted`、`writeback_complete`；
- 生命周期中是否曾出现 `ActionFailed`。

判定规则：

```text
初始 EarlyStop：必须曾执行 EarlyStopAction。
初始非 EarlyStop：必须曾执行 HisoDecode 或 SisoDecode。
全部 code：最终必须 AlreadyDecoded、非 pending、非 forced-evicted、写回完成，
           且生命周期中不得出现 ActionFailed。
```

## 5. 结论

对于本次运行中已经完成 FIFO 服务的 8,425 个 batch：

```text
N_non_early_stop_never_decoded = 0
N_final_pending                = 0
N_final_forced_evicted         = 0
N_writeback_incomplete         = 0
N_action_failed                = 0
```

因此可以确认：

> 在 `Eb/N0=3.09 dB、R_buf=138` 的本次实际运行中，对于所有已完成服务的 batch，Buffered FIFO 已经消除了“非 EarlyStop code 永远未获得 HISO/SISO 译码机会”的问题。

这不是由 BER 间接推断，而是逐 `(batch, code)` 生命周期得到的直接结果。

## 6. CSV 的一个重要阅读注意事项

不能只看一个 code 的**最后一条** CSV 记录中的 `final_action`。

例如汇总最后记录时会出现：

```text
Produced,Unscheduled
```

这不表示该 code 从未获得资源。其含义是：该 code 已在前一次服务中产生并写回结果，后续 retry 服务时成为 `AlreadyDecoded`，调度器按设计不再给它重新分配 HISO/SISO；状态刷新后 `final_action` 可以显示为 `Unscheduled`。

因此第 1 步的正确判据必须是：

```text
沿整个生命周期检查是否曾出现 HisoDecode 或 SisoDecode，
而不是检查最后一条记录的 final_action。
```

## 7. 本测试的范围边界

有限输入帧共到达 8,449 个 batch，而本次正常仿真结束时只完成服务了 8,425 个 batch，FIFO 中保留 24 个帧尾 batch。当前软件未实现 tail drain，且 BER 统计裁掉帧尾两个 window。

因此本测试严格证明的是：

> 对已经被 FIFO 完成服务、并构成当前有效分析区域的 8,425 个 batch，5.1 成立。

它尚未验证末尾 24 个未 drain batch 的最终状态。若以后需要将 5.1 表述扩展为“有限输入帧的所有 arrival batch 都成立”，需要增加仅用于软件验证的 tail drain 模式。

## 8. 后续第 2 步

第 1 步已经确认译码机会覆盖性。下一步应验证：即使所有非 EarlyStop code 都获得了 HISO/SISO，Buffered FIFO 的输入、动作、history/extrinsic 写回和最终 LLR 是否与现有的 `shared=ON、HISO/SISO=32/32、GlobalPriority` 充足资源参考方案一致。该参考路径可直接运行；只有这一层已经对齐后，才有必要再引入 `shared=OFF` 的每级独立 32/32 路径作更严格的第二层参考。
