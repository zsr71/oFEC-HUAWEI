# 仓库结构说明

以下内容概述了 `newcode` 仓库的顶层结构，以及各目录/文件在开发流程中的作用，方便快速了解项目布局。

## 目录一览
- `apps/`：存放面向最终用户或实验的可执行入口，例如 `ofec_sweep.cpp` 等，会链接 `src` 与 `include` 中的核心库。
- `src/`：主要的功能实现与通用模块源文件，通常与 `include/` 中的头文件配套，供 `apps` 和 `tests` 复用。
- `include/`：项目公开或共享的头文件，集中管理接口定义、公共常量、数据结构等，利于跨模块复用。
- `tests/`：测试代码与相关资源，对 `src` 提供的功能做单元或集成验证，建议通过 CTest 或自定义脚本运行。
- `data/`：示例或实验所需的数据文件，运行 `apps` 或 `tests` 时可在此读取输入或保存结果。
- `build/`：构建输出目录（由 CMake/Ninja/Make 生成），包含中间文件、目标文件与最终可执行文件；通常不纳入版本管理。
- `matlab/`：与 MATLAB 相关的脚本或分析工具，可用于对算法做前期验证、绘图或结果对比。
- `doc/`：文档目录（当前文件所在位置），用于沉淀架构说明、使用手册或实验记录，便于团队协作。
- `Ubuntu-22.04/`：针对特定环境（如 Ubuntu 22.04）的配置、脚本或依赖记录，可在部署或复现实验时参考。
- `.vscode/` 与 `.VSCodeCounter/`：VS Code 工作区配置及代码统计工具生成的文件，帮助统一开发体验与统计数据。

## 根目录文件
- `CMakeLists.txt`：项目的构建入口，定义所有目标、依赖与编译选项，是运行 `cmake` 的核心配置。
- `1.cpp`、`pushtest.cpp`：零散/临时的实验代码，通常用于验证某个想法或复现最小示例。
- `.gitignore`：版本控制忽略规则，避免将编译产物、临时文件等提交到仓库。

## 推荐工作流
1. 在 `src/` + `include/` 中实现或修改核心逻辑。
2. 通过 `apps/` 的示例程序或 `tests/` 的单元测试验证功能，并根据需要读取 `data/` 里的样例输入。
3. 使用根目录 `CMakeLists.txt` 配合 `build/` 目录完成一次独立的构建，确认生成的可执行文件可在目标环境（如 `Ubuntu-22.04/`）正常运行。
4. 将相关说明或实验记录补充到 `doc/`，使后续成员能够快速理解上下文。
