不知道你们有没有看过之前那篇论文。实际上，一个码字是可以定义置信度的。

比如外信息本身就可以反映一定的置信度。

一个码字译码之后得到 D 码字、C 码字，可以从这些码字之间的关系得到一些信息。

比如 D 码字很小，那么它译码成功的概率可能比较高。

如果 D 码字和 C 码字之间的距离很大，那么这个码字译码成功的概率也比较高，因为没有其他候选和它形成强竞争，所以置信度比较高。

如果 D 码字和 C 码字非常接近，那么这个码字译码成功的置信度就比较低。

所以可以考虑把码字置信度也作为调度中的一个因素。

比如一个码字的置信度很低，到底应该让它继续译码，还是不让它继续译码？

或者说，如果能够判断某个码字本身错误比较少，那是不是应该优先译码它？

这些都可以作为一种策略来考虑。

我觉得总体上，如果这个码字比较容易译出来，那肯定应该优先给它译码机会。

也可以综合考虑缓存大小和待译码码字的情况。

比如缓存空间还很充足，那就尽可能把能译的都译掉。

如果缓存空间已经不够了，就优先处理那些比较容易译出来的码字。

例如一个码字可能只错了 3 个 bit 或者 4 个 bit，很容易就能够译出来，那就优先把它译掉。
