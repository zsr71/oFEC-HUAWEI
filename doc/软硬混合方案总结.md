# 一、整个方案的核心想法

---

这套方案的本质思路可以概括成一句话：

> **先用很便宜的 syndrome 分类，把“明显不用处理”和“明显能硬纠”的码字快速分出去；只有“疑似两错”或“明显硬解不了”的码字，才进入更重的 BCH 定位或软译码流程。**

也就是说，它不是“一上来所有码字都走完整 BCH 硬译码器”，而是分成两层：

## 第 1 层：快速分类（便宜）

只根据：

$$
S_0,\; S_1,\; S_3
$$

对每个码字做快速判断：

* 是否 **clean**
* 是否只是 **扩展 parity 位错误**
* 是否明显是 **1 错**
* 是否是 **疑似 2 错候选**
* 是否已经明显 **hard fail**

这一层非常适合硬件并行做，代价小。

---

## 第 2 层：精细处理（较贵）

只对少量难处理的码字进一步操作：

* 对 **2 错候选**：走一个简化的 t=2 BCH 硬件定位流程

（闭式公式生成 locator polynomial + Chien search）
* 对 **定位失败** 的：送入 **Chase / 软译码**
* 对 **定位虽成功但不放心** 的：可以标记成 **suspicious**，再交给软译码复核

---

## 为什么这个方案适合硬件？

因为它能把复杂度分层：

### 很便宜的事情：

* 比较 $S_0$ 是否为 0/1
* 比较 $S_1,S_3$ 是否为 0
* 检查是否满足：

$$
S_3 = S_1^3
$$

这些都很便宜。

### 比较贵的事情：

* 计算 two-error locator polynomial
* Chien search
* Chase / 软译码

这些只让少数码字去做。

# 二、最终判断表（推荐直接用）

---

下面这个表，就是你可以直接拿去做硬件/流程设计的**主判断表**。

## 1. 第一层：快速分类表

| 编号 | 条件 | 类别 | 解释 | 处理 |
| --- | --- | --- | --- | --- |
| A | $S_0=0,\;S_1=0,\;S_3=0$ | **Clean** | 无错误 | 直接早停 / 不处理 |
| B | $S_0=1,\;S_1=0,\;S_3=0$ | **ParityOnly** | 只扩展 parity 位出错 | 直接翻 parity 位 |
| C | $S_1\neq0,\;S_3=S_1^3,\;S_0=1$ | **OneMain** | BCH 主体 1 bit 错 | 直接硬纠 1 位 |
| D | $S_1\neq0,\;S_3=S_1^3,\;S_0=0$ | **OneMainPlusParity** | BCH 主体 1 bit 错 + parity 位错 | 翻 BCH 位置 + parity 位 |
| E | $S_0=0,\;S_1\neq0,\;S_3\neq S_1^3$ | **TwoCandidate** | 疑似 BCH 主体 2 bit 错 | 进入 two-error 定位流程 |
| F | 其他情况 | **HardFailCandidate** | 不符合 clean / parity / 1-error / 2-candidate | 直接送 Chase / 软译码，或标记 fail |

---

## 2. 第二层：two-error 精细判断表

对于 **TwoCandidate**，再做：

$$
P=\frac{S_1^3+S_3}{S_1}
$$

构造错误定位多项式：

$$
\Lambda(z)=z^2+S_1z+P
$$

然后做 Chien search / 根搜索。

| 条件 | 最终类别 | 处理 |
| --- | --- | --- |
| 找到 2 个合法根 | **TwoMain** | 翻转对应的两个 BCH 位置 |
| 找不到 2 个合法根 | **HardFail** | 送 Chase / 软译码 |

---

## 2.1 硬件拍级时序影响

`TwoCandidate` 会带来一个重要的硬件调度影响：第二拍做完 fast classification 后，仍然不能完整确定哪些行需要进 Chase。

推荐时序如下：

```text
第 1 拍：
  计算 32 个码字的 S0 / S1 / S3。

第 2 拍：
  做 fast classification。
  Clean / ParityOnly / OneMain / OneMainPlusParity：
    可以直接确定为前端硬完成。
  明显 HardFailCandidate：
    可以直接确定为 Chase 候选。
  TwoCandidate：
    只能送入 BCH hard decoder 或 two-error locator + Chien search 做确认。

第 3 拍：
  TwoCandidate 确认结果返回。
  确认成功：
    进入 TwoMain / HardFinish。
  确认失败：
    进入 HardFail / Chase 候选。
  此时才能形成完整的 Chase candidate mask。
```

推荐最终组合逻辑：

```text
hard_finish_mask =
    hard_finish_mask_fast | two_hard_finish_mask

chase_candidate_mask =
    chase_mask_fast | two_chase_mask
```

因此，MUX / Chase 调度最好放在第三拍之后统一做。第二拍提前调度部分 Chase 行虽然能降低延迟，但会引入 SISO 预算抢占和重排问题：如果第二拍已经用完 Chase 名额，第三拍返回的 two-fail 行就需要额外处理。

---

## 3. 如果还想再加一层“可靠度保护”

这是为了防止 miscorrection。

即使找到了两个根，也不一定真的就是“真实两错”。

所以你还可以加一个可靠度判断：

| 条件 | 类别 | 处理 |
| --- | --- | --- |
| 两个待翻转位置的 ( | LLR | ) 都较小 |
| 两个待翻转位置的 ( | LLR | ) 很大 |

也就是说最终可以是：

```
TwoCandidate   ├─ Chien 成功 + 可靠度合理 → TwoMain   └─ Chien 失败 或 可靠度可疑 → HardFail / Suspicious
```

# 四、最适合工程实现的“分级状态表”

---

如果你最后要在代码/RTL/文档里定义状态，我建议你这样定义。

## 一级：快速分类状态（FastClass）

```
enum FastClass {    CLEAN,    PARITY_ONLY,    ONE_MAIN,    ONE_MAIN_PLUS_PARITY,    TWO_CANDIDATE,    HARD_FAIL_CANDIDATE};
```

## 二级：最终分类状态（FinalClass）

```
enum FinalClass {    FINAL_CLEAN,    FINAL_PARITY_ONLY,    FINAL_ONE_MAIN,    FINAL_ONE_MAIN_PLUS_PARITY,    FINAL_TWO_MAIN,    FINAL_HARD_FAIL,    FINAL_SUSPICIOUS};
```

### 状态转换关系

| FastClass | 后续动作 | FinalClass |
| --- | --- | --- |
| CLEAN | 无需进一步处理 | FINAL_CLEAN |
| PARITY_ONLY | 直接翻 parity 位 | FINAL_PARITY_ONLY |
| ONE_MAIN | 直接翻 BCH 1 位 | FINAL_ONE_MAIN |
| ONE_MAIN_PLUS_PARITY | 翻 BCH 1 位 + parity 位 | FINAL_ONE_MAIN_PLUS_PARITY |
| TWO_CANDIDATE | 做 locator + Chien | FINAL_TWO_MAIN 或 FINAL_HARD_FAIL |
| HARD_FAIL_CANDIDATE | 直接送 Chase/软译码 | FINAL_HARD_FAIL |

如果再加上 LLR 保护：

| 条件 | FinalClass |
| --- | --- |
| TwoCandidate + Chien 成功 + 可靠度合理 | FINAL_TWO_MAIN |
| TwoCandidate + Chien 成功 + 可靠度可疑 | FINAL_SUSPICIOUS |
| TwoCandidate + Chien 失败 | FINAL_HARD_FAIL |

# 五、32 个码字在系统中的调度策略

---

你这里不是只处理 1 个码字，而是 **32 个码字一起进来**。

所以分类完以后，建议做下面的调度：

## 调度优先级建议

| 优先级 | 类别 | 动作 |
| --- | --- | --- |
| 最低 | Clean | 直接跳过 |
| 低 | ParityOnly | 直接改 parity |
| 低 | OneMain | 直接硬纠 |
| 低 | OneMainPlusParity | 直接硬纠 |
| 中 | TwoCandidate → TwoMain | 做定位后硬纠 |
| 最高 | HardFail / Suspicious | 送 Chase / 软译码 |

换句话说：

> **绝大多数轻码字在前端就处理掉；真正占资源的软译码，只留给少数困难码字。**

这就是整个分流方案的最大价值。

## 方案总结（正式版）

针对 eBCH(256,239) 组件码的早停与分流需求，可基于 $S_0,S_1,S_3$ 构建分层式 syndrome 分类与译码架构。其总体思路为：首先通过低复杂度的 syndrome 快速分类模块，对输入码字进行 clean、parity-only、single-error、single-error-plus-parity、two-error-candidate 与 hard-fail-candidate 分类；其中 clean 与单错类码字直接在前端完成早停或硬纠，仅对 two-error-candidate 码字进一步启动 t=2 BCH 错误定位流程。对于 two-error-candidate，通过闭式公式生成错误定位多项式，并结合 Chien search 进行根搜索，若存在两个合法根，则判定为可纠两错并执行翻转修正，否则转入 Chase 或其他软辅助译码流程。必要时，可进一步引入基于 LLR 的可靠度门限，以抑制 miscorrection。该方案能够通过“轻前端分类 + 重后端按需启动”的方式，有效降低硬件复杂度与平均译码时延，同时提高软译码资源利用效率。
