# HISO 外信息幅度扫描实验（2026-08-27）

## 1. 目的

验证 Level 5/6 的 Hybrid HISO 在硬译码成功后写回的外信息幅度
`HYBRID_HARD_LLR_MAG_LIST`，从原来的 `99,99` 降低后，是否会改变最终
Post-FEC BER；并区分两类现象：

1. 在 FIFO 正常稳定、没有 forced eviction 时，幅度本身及其后续迭代传播带来的
   性能变化；
2. 幅度过低使 EarlyStop 率下降、FIFO 服务率不足后造成的强制顶出。这种 BER 崩坏
   不能被解释为单纯的“较小硬外信息幅度更差”。

本轮只改变 Level 5/6 的幅度列表第 5、6 项；Tile 1--4 固定为零，不启用 Hybrid
hard-finish。

## 2. 运行条件

所有扫点使用同一帧、同一信道噪声和同一 BER 比较区域：

| 项目 | 固定值 |
|---|---|
| Eb/N0 | 3.065 dB |
| 信息 bit 数 | 60,014,592 |
| bitgen / channel seed | 20260319 / 3182026 |
| LLR | `qfloat<6>` |
| 比较 bit 数 | 58,608,000 |
| BER 裁剪 | 固定裁剪 1,406,592 bit（前四个及末两个 window），与 `R_buf` 无关 |
| Level5/6 shared | ON |
| Buffered FIFO | ON |
| `R_buf` | 16,000 block rows |
| 帧尾 | drain ON，离线实验中继续服务直到 FIFO 清空 |
| Hybrid HISO 准入 | 全类别，mask=`0xF` |
| 共享资源 | 8 HISO + 8 SISO |
| 调度 | Group4 LoadSortedMultiround，`group4_max_entries=8` |

每个点仅设置：

```text
OFEC_HYBRID_HARD_LLR_MAG_LIST=0,0,0,0,M,M
```

运行时环境变量解析位于 `apps/ofec_single.cpp`。未设置该变量时仍严格使用原默认
`{0,0,0,0,99,99}`，因此本次添加的是实验覆盖入口，不改变默认解码流程。

## 3. 幅度在当前代码中的真正含义

HISO 对 BCH 硬译码后的合法硬码字 `cw`，先构造：

```text
lpost[i] = sign(cw[i]) × M
y2[i]    = lpost[i] - lin[i]
```

随后 Level 5/6 的统一后处理对 produced row 乘以该 tile 的 `ALPHA`、进行 qfloat
量化，并按原 writeback 映射写入连续 SRAM；Level 6 的 produced 行还会更新其
history。故实际写回近似为：

```text
written_extrinsic[i] = quantize(ALPHA × (sign(cw[i]) × M - lin[i]))
```

所以这里的 `M` 不是一个只影响“当前 code 最终判决”的独立后处理参数。它会同时
改变：

```text
HISO 写回强度
→ 后续 batch / Level 6 history 的 lin
→ EarlyStop、Hybrid 分类、HISO/SISO 动作集合
→ FIFO 服务节拍与最终 BER
```

因此本扫描测到的是实际闭环译码性能；不同幅度点不应被表述为“除了 HISO 幅度外所有
code 动作完全相同”。不过，可以用 `forced_evicted=0` 排除最严重的 FIFO 容量溢出
因素。

## 4. 完整帧扫描结果

| L5/L6 M | Post-FEC errors | BER | forced eviction | completed | max FIFO depth | 最小 `S_t` | 结论 |
|---:|---:|---:|---:|---:|---:|---:|---|
| 99（原默认） | 159 | `2.71294e-6` | 0 | 16,897 | 1,888 | 11,576 | 稳定基线 |
| 70 | 175 | `2.98594e-6` | 0 | 16,897 | 1,886 | 11,590 | 比 99 差 |
| 65 | 135 | `2.30344e-6` | 0 | 16,897 | 1,885 | 11,592 | 优于 99 |
| 60 | 81 | `1.38206e-6` | 0 | 16,897 | 1,873 | 11,620 | 明显改善 |
| 55 | 74 | `1.26263e-6` | 0 | 16,897 | 1,877 | 11,616 | 当前已测最佳 |
| 50 | 93 | `1.58681e-6` | 0 | 16,897 | 1,898 | 11,518 | 比 55 差，仍优于 99 |
| 45 | 172 | `2.93475e-6` | 0 | 16,897 | 2,000 | 11,024 | 比 99 略差 |
| 30 | 134,754 | `2.29924e-3` | 4,548 | 12,349 | 8,001 | 0 | FIFO 失稳，不能作纯幅度比较 |

注：`S_t` 是解码窗口相对基准的可恢复位置；`S_t=0` 表示窗口已顶到缓冲区边界。
在 30 点出现 `S_t=0` 后，为保证输入输出节拍只能继续推进，未完成 batch 被 forced
evict。表中 30 的 BER 因而混有大量未完成译码的影响。

相对原默认 `M=99`，本固定帧上：

| 对比 | 错误数变化 |
|---|---:|
| `99 → 60` | 159 → 81，减少 49.1% |
| `99 → 55` | 159 → 74，减少 53.5% |
| `99 → 50` | 159 → 93，减少 41.5% |

## 5. 服务稳定性与 EarlyStop 观察

除 `M=30` 外，45--99 的所有点均满足：

```text
forced_evicted = 0
completed      = 16,897（所有 arrival batch 均完成）
frame-end drain 后 FIFO 为空
```

故 45--99 的 BER 差异不能归因于缓冲区溢出或帧尾 pending 未清空。它们的 Level 5/6
每行 EarlyStop 率也接近：Level 5 均为约 74.7%，Level 6 为约 98.1--98.2%。

`M=30` 则已进入不同工作区：Level 5 / 6 每行 EarlyStop 率降到约 60.0% / 41.9%，
服务需求持续超过 8 HISO + 8 SISO 的可供给能力；最终 `min_S_t=0`、4,548 个 batch
被 forced evict。因此 30 的失败表明存在稳定性下界，但不证明“硬外信息越小，BER
一定越差”。

## 6. 本轮可确定的结论

1. **会变化。** 在完全相同的完整帧、信道和 BER 比较区间，改变 Level 5/6 HISO
   外信息幅度会明显改变最终 BER。
2. 在当前固定工作点，幅度与 BER **不是单调关系**：`50 → 55 → 60 → 65 → 70`
   的 errors 为 `93 → 74 → 81 → 135 → 175`。因此不能用“幅度越低越能抑制错误硬
   输出”这一单一机制解释全部结果。
3. 在当前已扫点中，`M=55` 为局部最佳：74 errors，较原 99 的 159 errors 少 53.5%；
   `M=60` 也显著改善（81 errors）。这已经证实：保留 HISO 动作的前提下，降低其
   写回置信度可以显著缓解原 99 的 BER 劣化。
4. `M=45` 和 `M=70` 虽然都没有 forced eviction，却分别得到 172 和 175 errors。这
   说明闭环中的量化边界、后续 LLR 演化和译码动作变化会产生局部起伏；单一 seed 上
   的 55 不应直接宣布为全局最优幅度。
5. `M=30` 引起 FIFO 失稳。这建立了实际设计约束：选择较低 HISO 置信度时，不仅要
   看无 forced eviction 下的 BER，也要验证 EarlyStop 和长期服务能力仍足以维持窗口。

## 7. 与此前 TwoMain 机制的关系

此前真值观测已经确认，当前 HISO 相对纯 SISO 的主要 BER 风险来自 TwoMain：当其
实际硬判错误数超过 BCH 纠错半径时，BCH 仍可能产出**代数合法但不同于真实发送码字**
的硬码字；固定幅度 99 会把该错误码字方向以较强外信息写回。

从 99 降至 55/60 的改善与该机制相容：错误合法硬输出的注入强度被削弱，后续软信息
有更多机会将其纠回。但本轮尚未对每个幅度逐 code 重新统计错误 HISO 输出与最终错误
位置，所以不能把“55 的全部改善量”严格等同于某一类 TwoMain 错误的直接消除。

同样，55 仍显著差于当前纯 SISO 参考（11 errors）；这说明“统一缩小所有 HISO 的
幅度”可缓解问题，但尚未达到完全取代 TwoMain 走 SISO 的效果。

## 8. 下一步建议

1. 先在 `M=52、55、58、60` 做多 seed 重复，检查 55 附近的优势是否具有统计稳定性；
2. 对 55、60、99 打开已有的只读 HISO 真值观测，比较错误合法 HISO 输出次数、其
   写回幅度分布及与最终错误位置的关联；
3. 保持 `forced_evicted=0` 作为幅度性能对比的必要条件。若要研究低幅度的稳定性边界，
   则单独记录 EarlyStop、服务率、`min_S_t` 和 forced eviction，不与正常 BER 点混表；
4. 幅度优化与类别策略可分开比较：例如以 `mask=0x7`（TwoMain 改走 SISO）为性能
   参考，再判断“55 的全类别 HISO”是否值得以吞吐换取其剩余 BER 差距。
